# Chat SDK 4.44.0

`@json-render/chat` renders a card spec into a Chat SDK card and peers `chat ^4.43.0`, so `chat` and the three adapter
packages move together from 4.41.1 to 4.44.0, the latest stable release. Neither adapter removed a method the host
reaches into (`parseSlackMessage`, `handleForwardedMessage`, `postMessage`); both only added methods.

The Discord patch shrinks to one hunk, the one-week auto-archive on the thread the adapter opens for a mention. Its
packet snapshot is gone, because 4.42 forwards the gateway packet as it arrived on the wire. Its three sibling-bot hunks
are gone too: they sit in `setupLegacyGatewayHandlers`, which runs only when no forwarding URL is passed. The host has
passed one since before those hunks were written, so they never ran, and forwarding hands every bot's message to the
host. The host's `__nanoclawDiscordSiblings` global, read only by those hunks, goes with them. The shared patch keeps
both of its changes. 4.44 moved `replaceBareMentions` into a chunk file that both adapters still reach through the
package entry, and upstream 4.44 still rewrites an `@name` inside a ``double-backtick`` span.

Upstream asks consumers to take `mdast-util-from-markdown` 2.1.0 and `micromark-extension-gfm-table` 2.1.2, which fix
slow parsing of long lists and large tables, and to keep `micromark` at 4.0.2. The lockfile does exactly that. Both
moves are inside the ranges `chat` declares, so they ride on its section below.

## chat 4.41.1 → 4.44.0

Source: https://github.com/vercel/chat/blob/main/packages/chat/CHANGELOG.md (4.42.0 through 4.44.0)

- 4.44: an inbound message past a parse budget (16,384 characters, or the emphasis, bracket, autolink, nesting and tree-depth limits) skips markdown parsing, and its `formatted` holds the text verbatim; the host rebuilds the agent's text from `formatted` · test: src/channels/slack-live-path.test.ts
- 4.44, Slack: on that fallback a composer list keeps the decimal references (`&#95;`, `&#46;`) the adapter writes for literal punctuation, so `source_data.x` would reach the agent as `source&#95;data&#46;x`; a list under 16,384 characters can cross the budget once rendered. The host decodes decimal references after the adapter's own fallback conversion (`decodeFallbackReferences` in src/channels/slack.ts), the order the parse uses, and leaves code alone as the parse does, so a typed `&lt;`, `&amp;`, `&#95;` or `<@U…>` in a list, and a reference inside code, arrive as typed · test: src/channels/slack-live-path.test.ts
- 4.44: the Discord gateway path builds its messages through the same budgeted parse; the live-path cases run it under the budget · test: src/channels/discord-live-path.test.ts
- 4.44: `renderList` indents a list nested under an ordered item to the item's content column and keeps a blank line between two blocks in one item; Discord renders outbound lists through it, while Slack sends a message's markdown as `markdown_text`, which Slack renders itself, and uses the helper only where it converts markdown to mrkdwn · not covered: no outbound test posts a list nested under an ordered item; the old two-space indent turned those items into siblings, so the change only repairs output
- 4.44: `requestApproval()` from `chat/workflow` verifies clicks against a stored receipt · not covered: the host never imports `chat/workflow`; its approvals are its own module
- 4.43: `startTyping` receives the current message id as `TypingOptions.messageId` · not covered: an optional argument the host's typing module does not pass, and the adapters treat as absent
- 4.43: `stringifyMarkdown` takes a `handlers` option; WhatsApp output keeps literal markers · not covered: no WhatsApp adapter is installed, and the host passes no handlers
- 4.42: `chat/adapters` is deprecated and re-exports `@chat-adapter/catalog` · not covered: the host never imports `chat/adapters`
- 4.42: `TextInput` becomes a card child and `ActionEvent` gains `values` · not covered: the host puts no text input on a card; its secret-intake form stays a modal
- 4.42: a handler-only `onNewMessage` overload, invalid arguments throw at registration, and a global or sticky pattern matches every message; the bridge registers one non-global pattern, and an unmentioned channel message still arrives through it · test: src/channels/slack-live-path.test.ts
- 4.42: AI tool factories from `chat/ai` reject unscoped calls inside a handler · not covered: the host never imports `chat/ai`
- 4.42: `Button` and `LinkButton` take `visibleTo`; posts take `aiGenerated` · not covered: optional fields the host does not set
- 4.42: dedupe, lock, queue and turn keys gain an installation scope when an adapter reports one · not covered: the host runs each Slack adapter with one bot token, and `SlackAdapter.getConcurrencyScope()` returns `undefined` whenever a bot token is configured, so its keys in the SQLite state are unchanged
- 4.42: modal context lasts until the modal closes · not covered: the secret-intake modal submits once and closes; a resubmit after a validation error keeps more context than before, never less
- 4.42: Workflow DevKit threads create their abort signal on first use · not covered: the host runs no workflows

## @chat-adapter/slack 4.41.1 → 4.44.0

Source: https://github.com/vercel/chat/blob/main/packages/adapter-slack/CHANGELOG.md (4.42.0 through 4.44.0)

- 4.44: a list from Slack's composer arrives as a list, nested items included, built from the `rich_text` blocks instead of the flattened `• ` lines in `event.text` · test: src/channels/slack-live-path.test.ts
- 4.44: on fallback the adapter decodes entities · test: src/channels/slack-live-path.test.ts
- 4.44: on fallback the adapter renders mentions, channels and links · not covered: the over-budget case carries an escaped mention as text, not a real mention, channel or link token
- 4.44: Slack's limits are checked once across a message's text, blocks, attachments and table cells · not covered: the live-path case crosses the budget with one list, not across parts; a message the aggregate check sends to fallback reaches the agent through the same fallback the case pins
- 4.44: `app_uninstalled` dispatches to `onUninstalled`, and `tokens_revoked` skips the installation lookup · not covered: the host registers no `onUninstalled` handler and its Slack apps do not subscribe to `app_uninstalled`
- 4.44: `isBotMention()` export and a `botUserId` option on `withBotToken` · not covered: additions the host does not call
- 4.43: a bot mention that appears only inside code is not a mention, for `app_mention` and `message` events alike · test: src/channels/slack-live-path.test.ts
- 4.43: a message whose blocks are all section, header, context, image, divider, actions or table blocks is read from those blocks rather than from its notification text, so an integration's or another bot's Block Kit post reaches the agent with its body · test: src/channels/slack-live-path.test.ts
- 4.42: card text past Block Kit's length limits is cut, with the card's buttons kept, where Slack used to reject the card; an approval or choice card's question (`install_packages` lists up to 20 packages, a bash-gate card shows the command) could then show only part of what Approve grants. On Slack the bridge posts no card whose body is over the cap once the adapter expands its emoji, nor a question card with an option label over 75 characters, which the adapter cuts so that two choices can read alike; Slack refused both before 4.42. This covers question, approval and secret-intake cards and the card edited after a click. `request_choice` and bash-gate already fit their cards to the approvals card budget; `install_packages` and other approval creators do not yet check it before creating the approval · test: src/channels/chat-sdk-bridge.test.ts
- 4.42: incoming messages keep literal text and code formatting, and email and phone links parse · not covered: no live-path case sends literal markers or a phone link; the change keeps characters the old parse dropped
- 4.42: backward thread-history reads follow every `conversations.replies` page before taking the newest messages; the thread context loaded on a wake (`src/thread-context.ts`, through the bridge's `fetchThreadHistory`) reads this way, so a thread longer than one page now yields its newest replies, where it used to yield older ones, at one API call per page · not covered: no test serves a multi-page thread to the adapter; recovery pages Slack itself and is unaffected (src/channels/slack.test.ts)
- 4.42: `stream()` returns every message id and closes task cards when a segment rotates · not covered: the host does not post through native Slack streaming
- 4.42: `uploadSlackFiles` takes `blocks`, and `Button`/`LinkButton` take `visibleTo` · not covered: options the host does not pass
- 4.42: concurrency keys are scoped per installation in multi-workspace mode · not covered: see the `chat` section; a single-token adapter reports no scope
