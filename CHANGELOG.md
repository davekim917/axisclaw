# Changelog

All notable changes to NanoClaw will be documented in this file.

## [Unreleased]

- [BREAKING] **Fable's default effort moves to `high`.** `defaultEffortForModel` (`container/agent-runner/src/providers/claude.ts`) now returns `high`, not `medium`, for the word `fable` and every `claude-fable-*` id. Only a Fable path with **no effort set at any layer** moves (chat `-e`, session sticky, `providerConfig.effort`, wiring `default_effort`, `container.json` `effort` / `defaultEffort`, a Claude `providerFallback.effort`, task `effort_pin`, subagent frontmatter); every explicit pin keeps its value. Opus, Sonnet and Haiku defaults and the effort clamp are unchanged. Anthropic's Fable 5.2 guidance is to start at `high`; the model stops early more often at `low` and `medium`. Cost per moved turn rises. **Deploy needs a host restart** (runner source is a boot snapshot), no image rebuild; adopted containers keep `medium` until they respawn. **Migration — pin `medium` BEFORE you deploy where you want to keep it:** [docs/claude-default-model.md](docs/claude-default-model.md#current-fable-default-effort-high-2026-11-11) (detect / why / fix / verify / rollback).
- [BREAKING] **Claude subagents default to Opus.** The Claude spawn env sets `CLAUDE_CODE_SUBAGENT_MODEL` to `DEFAULT_OPUS_MODEL`, so a subagent that neither its Agent call nor its definition gives a model now runs Opus instead of inheriting its parent's model: a Fable or Sonnet session builds with Opus subagents. A model on the Agent call or a definition's `model:` (including `inherit`) still wins; a live-path test holds the CLI to that. A group's `settings.json` pin of the variable is scrubbed at spawn. Codex and OpenCode are untouched. **Deploy:** `scripts/deploy.sh` (host rebuild and restart); adopted containers keep inheriting until they exit. **Migration:** [docs/claude-default-model.md](docs/claude-default-model.md#history-2026-11-11--subagents-default-to-opus) (detect / why / fix / verify / rollback).
- **Live Discord admits a bot's message only from a known NanoClaw sibling, as recovery already did.** The gateway forwards every bot's message, so an integration's or a stranger's bot could wake an agent and enter its context; now one predicate in `src/channels/discord.ts` decides for both paths, and a bot message dropped on the live path is logged. In the 30 days before the change no other bot posted in a wired channel. A sibling whose identity fetch failed at startup is not admitted by the others until the next restart. **Deploy:** host restart.
- [BREAKING] **Agents post native cards from a json-render spec.** `send_card` now takes `{ spec, fallbackText }`, where the spec is built from `@json-render/chat`'s components: Card, Section, Text, Fields/Field, Table, Chart (pie, bar, line, area), Divider, Image, and Actions holding LinkButtons. The host checks the spec against `src/channels/card-spec.ts` and the platform's caps, then posts it through the Chat SDK. On Slack that means one table, two charts, 10 fields per group and 100 rows, and the host also renders the card with the converter the adapter posts with, and refuses what Slack would refuse, drop or show as text, or cut from a Text, Field or subtitle (past 50 blocks or 25 buttons, a Text over 3,000 characters, a table or chart Slack can't show natively). A title, button label or alt text past its cap is shortened with an ellipsis. On Discord the host refuses an Image child or a Table caption, which the embed drops, a Chart yLabel, which it drops, repeated Chart categories, which it shows with the wrong values, and a line break in a Table cell, which its text table turns into a space. It also refuses what Discord would reject: text past 4,096 characters, more than 25 fields, a field label over 256 characters or value over 1,024, more than 6,000 characters in all, more than 5 rows of buttons, a button label over 80 characters or a URL over 512. Both platforms left-align every Table column, and the guide says `align` is ignored. Slack gets native Block Kit, including data tables and charts, and Discord gets an embed. A rejected spec posts nothing. The tool waits for the host's verdict and returns every issue, so the agent can fix the spec and call again. `fallbackText` is required: the posted card is archived as that text for search, thread history and the mobile app, and the terminal channel prints it. Slack and Discord build their notification and their own fallback from the card itself. A session with no conversation, such as a task session, can't post a card. The old `{ card: { title, description, children, actions } }` shape and its bridge renderer are gone. A container adopted across the deploy keeps the old runner until it exits, and its old-shape cards are refused and logged rather than posted. Buttons that click back to the agent stay out of the catalog for now; that is `request_choice`'s job. **Deploy:** host restart; runner changes reach each group at its next spawn.
- **Chat SDK pinned to `4.44.0` (was `4.41.1`).** `chat`, `@chat-adapter/slack`, `@chat-adapter/discord` and `@chat-adapter/shared` move together, with the `/add-<channel>` install pins and `setup/install-github.sh`. What agents see changes in three places. A list typed in Slack's composer arrives as a markdown list with its nesting, where it used to arrive as flattened `•`/`◦` lines. A Slack message made only of Block Kit sections, headers, context, images, dividers, actions or tables (an integration's or another bot's post) arrives with its block text, not just its notification text. A message past the SDK's new parse budget (16,384 characters, or pathological nesting and emphasis) arrives as written rather than rebuilt from markdown. For an over-budget composer list, the host decodes the punctuation references Slack's adapter would otherwise leave in it (`&#95;` for `_`). The Discord patch shrinks to one hunk, the one-week auto-archive on the thread the adapter opens for a mention. Its packet snapshot is now upstream. Its sibling-bot hunks, and the `__nanoclawDiscordSiblings` global they read, are removed: they sat in a gateway mode the host never runs, and sibling handoffs arrive through gateway forwarding, which a live-path test now covers. The shared patch keeps the double-backtick mention fix, which upstream still lacks. `mdast-util-from-markdown` 2.1.0 and `micromark-extension-gfm-table` 2.1.2 come in for upstream's long-list and large-table parsing fixes, and `micromark` stays at 4.0.2 as upstream advises. Since 4.42 Slack's adapter cuts card text past 3,000 characters and keeps the buttons, where Slack used to reject the card. So on Slack the bridge posts no card whose body is over that cap once its emoji are expanded, nor a question card with an option label over Slack's 75-character button cap, as Slack refused both before 4.42; an approval never shows part of what Approve grants, or two choices alike. Ledger: `docs/dependency-changes/2026-11-10-chat-sdk-4.44.0.md`. **Deploy:** host restart; no image rebuild.
- **A container agent can no longer turn on a mod it writes.** Under `bypassPermissions` Claude Code loads an agent-written mod without asking, and a mod's hooks run above the runner's `PreToolUse` guards. The image now ships a root-owned `/etc/claude-code/managed-settings.json` with `allowManagedModsOnly`. No group uses a mod today. **Deploy:** agent image rebuild.
- [BREAKING] **`fable` means Fable 5.2, and the pinned CLI moves with it.** `DEFAULT_FABLE_MODEL` is now `claude-fable-5-2[1m]` (was `claude-fable-5-1[1m]`), so every `-m fable`, every `fable` wiring, group, task or `providerFallback` pin, every `model: fable` subagent, and the CLI's own calls through the word run Fable 5.2. A frozen `claude-fable-5-1[1m]` or `fable51` pin keeps Fable 5.1; repin it to `fable` to follow this and later bumps. Fable's default effort stays `medium`. New pinned aliases: `fable52` / `fable5-2` / `fable-5-2`. Claude Code goes 2.1.302 → 2.1.322 and the agent SDK 0.3.302 → 0.3.322 in lockstep (2.1.302 has no `claude-fable-5-2`), recorded in `versions.json`. **Deploy needs an agent image rebuild (and every `imageTag` group's image) and a host restart; adopted containers keep the old CLI until recycled.** **Migration:** [docs/claude-default-model.md](docs/claude-default-model.md#history-2026-11-10--fable-default-moves-to-52) (detect / why / fix / verify / rollback).
- **[BREAKING] The "Data read (recorded)" sources footer is on for every agent group.** `sourcesFooter` is now opt-out like `statusSubtext`: unset means on, and recorders run in every container. Opt a group out with `ncl groups config update --id <id> --sources-footer off` (writes `sourcesFooter: false`); `config get` shows the stored value and `effective_sources_footer`. **Deploy:** host restart; each group changes at its next spawn.
- **Claude and Codex container agents get an 800,000-token context window, and containers stop carrying the fast-jev-compaction wiring.** `DEFAULT_CLAUDE_AUTO_COMPACT_WINDOW` moves from 600,000 to 800,000, and Codex `model_context_window` from 600,000 to 800,000 with `model_auto_compact_token_limit` from 540,000 to 720,000, the same 90% ratio. Codex holds the value down to each model's `max_context_window`, so a model with a smaller maximum keeps that maximum. The spawn env no longer sets `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` or the `TYPESAFE_API_KEY` placeholder. Claude Code loads function-hook plugins with or without that flag, so a group stays off the plugin through `excludePlugins`, `exclude_plugins` or `data/plugin-scopes.json`. A group's explicit `autoCompactWindow` still wins, and each change reaches a group at its next spawn.
- **A keyed handoff opens its Discord thread at once.** The opening post of the work used to sit in the channel as a plain message until the next post under its key, which left the work out of the channel's thread list until then. A dispatched work session's keyed root post opens its thread the same way. **Deploy:** host restart, no image rebuild.
- **Discord threads opened by a dispatched work session stay visible for a week.** A keyed post from a `ncl tasks dispatch` session now opens its thread at 1 week of inactivity instead of 24 hours, so a scheduled watcher's topic threads stay in the channel list. Reports keep 24 hours, including keyed ones such as dbt alerts, because a report series opens its own threads. Threads already open keep the duration they were created with. **Deploy:** host restart, no image rebuild.
- **A revoked Claude token no longer strands a session: every Claude caller in a container now moves to the next token.** A 401 reaches the runner as an error `result`, not a thrown error, so nothing rotated on it: a session whose saved slot had been revoked failed every turn, and a rate-limit rotation that landed on a dead slot counted as recovered and saved that slot. Now a refused OAuth slot is skipped for the container's life and the turn retries on the next one, durable continuations rotate instead of pausing, the review form of `claude -p` rotates on a 401 and can reach the primary again after a rotation, and plain `claude -p` from a task script or a Codex or OpenCode container cycles through a supervisor that holds output until a run settles and never replays one that reached inference. A slot is saved only once it has served a turn. A lone token, API-key auth on the main turn, and a ring that refuses every slot end in the error they ended in before. Plain `claude -p` in a Claude OAuth session still fails with "Not logged in", deliberately. **Deploy:** host restart, no image rebuild. Each caller changes at its container's next spawn; an adopted container keeps its old runner until it exits.
- **The host now tells the owner when a Claude token is refused.** A new sweep duty, `oauth-slot-health`, runs a free `count_tokens` call once a day for every `CLAUDE_CODE_OAUTH_TOKEN*` in `.env`, directly rather than through any proxy, and sends one owner alert per refused slot name, once per condition. Only a 401 counts: a network failure, 5xx or 429 stays silent. A token value is never logged, stored or alerted. `data/oauth-slot-health.json` holds the next check time and the names already alerted, so a host that restarts more than daily neither postpones the check nor repeats an alert. **Deploy:** host restart, no image rebuild.
- **The takeover viewer shows the host the browser is on.** The DM's host says nothing once a page redirects, so the viewer now shows the current host above the page, from the browser's own address, in full.
- **The takeover viewer says when the host has stalled, and ignores taps until it clears.** A stall froze frames and input with no sign on the page, and taps made during it all landed at once when it ended. The viewer now checks a host-only `/alive` every second.
- **A browser takeover cannot file a listed provider's session in the shared directory.** `ncl browser takeover` now refuses a `--url` that could receive cookies from a host in another site's `browserSso` list, and names the site to use. Groups with no entry are unchanged. A `--url` host holding anything but letters, digits, dots, hyphens and underscores, or an IPv6 address, is refused for every group. On every takeover the owner's DM now prints the agent's `--reason` last, labelled as its own unchecked note, below the statement of what is handed over, with only letters, digits, spaces and light punctuation kept. **Deploy:** host restart, no image rebuild.
- **Codex container agents get a 600,000-token context window.** `model_context_window` moves from 400,000 to 600,000 and `model_auto_compact_token_limit` from 360,000 to 540,000, the same 90% ratio, matching the fleet's Claude window. Each turn can now carry more context, so a long Codex session uses more quota. **Deploy:** host restart, no image rebuild; a running container keeps its config until its next spawn.
- **A browser takeover can keep an identity provider's session for one configured site.** An app that re-mints its token through an identity provider came back signed out, because `ncl browser finish` keeps only the `--url` host's cookies and storage. A new optional `browserSso` map in `groups/<folder>/container.json` lists extra hosts per `--site`; only that file can widen, and a wildcard, a name under three labels or an invalid name refuses the takeover. The DM and the takeover page name the hosts and say the sign-in opens other apps, and on a widened takeover the agent's `--reason` is printed last, labelled as its own unchecked note. A widened login is private to the requesting agent group, at `/workspace/browser-state-private/<site>.json`. Sites with no entry behave as before. **Deploy:** host restart, no image rebuild; a group given an entry needs a restart so its private directory is mounted.
- [BREAKING] **A bind source an agent can write is checked and pinned on every spawn, and a link into a sibling's folder is read-only.** `buildMounts` now ends with one pass over every mount: a source inside an agent-writable tree (its group folder, session folder, workgroup tree, sibling folders, or any of the spawn's writable mounts) must resolve inside those trees, and is bound by its resolved path; otherwise the mount is dropped with `Refusing bind source that leaves the agent-writable trees`. A last check just before `docker run` aborts the spawn if a source was swapped for a link. A link into a sibling's folder now mounts read-only, as does a link into the workgroup tree in memory-only mode, and a path bound read-only over a writable parent stays read-only by every other route, including an agent's own `plugins/`. A writable bind landing on a read-only path is refused with `Refusing writable bind over a read-only path` instead of failing the spawn. **Affected:** a Codex or OpenCode sibling whose `standing-instructions.md` links to its source group can no longer edit it there; a link into a sibling's folder, such as a repo in a workgroup without the shared tree, mounts read-only. **Detect:** those WARN lines in `logs/nanoclaw.error.log`, or `EROFS` from the agent. **Fix:** edit from the group that owns the file, or move shared work into the workgroup tree. **Verify:** the next spawn's mounts. **Rollback:** revert this change and restart the host. **Deploy:** host restart, no image rebuild; a running container keeps its mounts until it exits.
- **A symlink in a group folder can no longer expose a group's `container.json` or a whole group folder.** The symlink overlay in `buildMounts` used to bind any target inside the workgroup read-write, so a link planted in an agent's own folder gave it a writable `container.json` (its own or a sibling's) at the next spawn. It now refuses a link whose real target is a group folder, a directory above one, or any `container.json`, logs `Refusing symlink-overlay mount of a group root or container.json`, and still spawns. Every member's `container.json` is also re-protected read-only from any other writable mount. Links to files and sub-directories keep working. **Deploy:** host restart, no image rebuild; a running container keeps its mounts until it exits.
- [BREAKING] **OpenCode credentials come from the OneCLI vault; no container gets an `auth.json`.** OpenCode groups and the headless `opencode` in every Claude and Codex container send the key `placeholder`, and the gateway injects the vault secret on `opencode.ai`. The per-group `~/.local/share/opencode-<folder>/auth.json` files are no longer read, each spawn removes an `auth.json` left in the session tree, and the runner's native-auth route (the `opencode.ai` NO_PROXY bypass, the `anthropic` auth.json gate) is gone. Each agent gets exactly one `opencode.ai` secret: its group's own (`container.json` `onecliSecrets`), else its workgroup's, else the new `NANOCLAW_OPENCODE_FLEET_SECRET`. An `anthropic/*` OpenCode model now needs an Anthropic API key registered with `--type anthropic`. **Deploy:** host restart, no image rebuild. Migration path (detect, why, fix, verify, rollback): [docs/opencode-vault-credentials.md](docs/opencode-vault-credentials.md).
- **Thread and session titles run Haiku 5.5 through the Claude Code CLI.** `callHaiku` (`src/llm.ts`) now runs `claude -p` at effort `low`, with no tools, settings, MCP or session, and its config isolated in `data/claude-title-cli/`. It still tries one subscription slot at a time, passing the slot's token to the CLI and reading its JSON result. On raw `/v1/messages` a subscription OAuth token refuses Haiku 5.5 for a caller that is not Claude Code, and v2's direct call could not move off Haiku 4.5. The CLI's own retries are off (`CLAUDE_CODE_MAX_RETRIES=0`), since `callHaiku` rotates slots itself. A title takes about 2–4 s, up from under 1 s. **Requires** `claude` on the service `PATH`: titles run whichever `claude` that PATH resolves first. **Deploy:** host restart.
- [BREAKING] **The Haiku default moves to Haiku 5.5, which takes effort, and the pinned CLI moves with it.** `DEFAULT_HAIKU_MODEL` is now `claude-haiku-5-5` (was `claude-haiku-4-5-20251001`), so every `-m haiku`, every `haiku` wiring, group, task or `providerFallback` pin, every `model: haiku` subagent, and the CLI's own calls through the word run Haiku 5.5 ($0.10/$0.50 per MTok up to 100K-token prompts, 1M context native). A frozen `claude-haiku-4-5` or `haiku45` pin keeps Haiku 4.5. Haiku 5.5 takes `-e low` through `max`; with no effort set at any layer it runs at `medium`. Haiku 4.5 ids still take none. New pinned aliases: `haiku55` / `haiku5-5` / `haiku-5-5`. Claude Code goes 2.1.290 → 2.1.302 and the agent SDK 0.3.290 → 0.3.302 in lockstep (2.1.290 has no `claude-haiku-5-5`), recorded in `versions.json`. 2.1.302 turns fork subagents on in SDK sessions, so the Claude spawn env now sets `CLAUDE_CODE_FORK_SUBAGENT=0` for agent and wiki containers. **Deploy needs an agent image rebuild and a host restart.** **Migration:** [docs/claude-default-model.md](docs/claude-default-model.md#history-2026-10-18--haiku-default-moves-to-55) (detect / why / fix / verify / rollback).
- **Codex subagents in containers always start with fresh context.** The runner's Codex PreToolUse chain denies a `spawn_agent` that would inherit the conversation: `fork_context: true`, a `fork_turns` other than `"none"`, or no control at all, which v2 treats as a full fork. Codex has no setting that turns forking off. Claude containers already run with `CLAUDE_CODE_FORK_SUBAGENT=0`, and host Codex is covered by the orchestrate plugin's spawn hook. A worker that shares its parent's context cannot check the parent's work, and a fork runs outside the model and effort its dispatch named. **Deploy:** host restart (the runner source is a boot snapshot), no image rebuild.
- [BREAKING] **A warning card names the holds its Go accepts.** `request_choice` with `approvalScope` and `decision.kind: "warning"` now needs `approvalScope.holds`, the exact `hold:` codes the release policy published for that head. The card shows them and the click receipt records them, so a Go covers only those holds; a warning card posted without them carries no release scope. **Affected:** any agent group that posts warning cards. Migration path (detect, why, fix, verify, rollback): [docs/release-card-holds-migration.md](docs/release-card-holds-migration.md).
- [BREAKING] **A scoped release card is now a warning or a release card, never a bare Ship / Hold.** `request_choice` with `approvalScope` takes `decision.kind: "warning"` (posted only when agents recommend not shipping: headline, asked, does, diverges?, risk, undo, holdingCosts, recommend, reviewers?, evidence, accept; buttons "Ship anyway — I accept <accept>" = `ship` and "Send back" = `send_back`) or `decision.kind: "release"` (headline, warnings, does, undo, reviewers?, evidence; "Ship release" = `ship`, "Hold" = `hold`). The `{question, ifItShips, evidence}` decision, a decision-less release card and the `NANOCLAW_RELEASE_CARD_DECISION_REQUIRED` switch are gone, and a click on a card posted before this change carries no `release_scope`, so it never counts as a release decision. **Affected:** any agent group whose procedure posts scoped release cards. **Detect:** `request_choice failed: decision.kind must be "warning" or "release"` (host) or `decision.kind must be …` (runner) in that group's session. **Fix:** move the procedure to the `kind` fields, then `ncl groups restart --id <group>` so the container's runner snapshot takes the new schema; re-post any card still open from before the deploy. **Verify:** the next card renders "Silence = nothing ships" and the two new buttons. **Rollback:** first retire every scoped card still open from before this change (re-post that PR's card under its `ship-ask:` key, which closes the old one): a revert makes its bare Ship click scoped again. Then revert this change and redeploy.

- **The backlog canvas no longer has a built-in Linear team.** The fallback was one deployment's own team key, so a board relying on it showed that deployment's team, not one this install configured. A group whose `backlogCanvas` omits `linearTeam` is now skipped, and each tick logs a warning naming the field to set in `groups/<folder>/container.json`.

- **A fallback session no longer loops back to a primary that cannot answer, and the "available again" line waits for the primary to answer.** A Codex group on its Claude fallback looped about every 18 minutes for a day: the provider-return sweep restarted the session on Codex and posted "codex is available again" at once, the fresh container timed out resuming that thread's saved Codex conversation (`thread/resume`, 60 s), the timeout was reported as a Codex outage, and the session went back to Claude. The cooldown never grew because a spawn that picked the primary cleared the failure streak before the primary had answered. Three changes: the thread line is now posted by the runner, only after the primary completes the return wake's turn (a failing return posts nothing); a `thread/resume` timeout drops the saved thread and replays the turn on a fresh Codex thread with a recap, telling the agent its memory was reset, instead of reporting `provider_unavailable`; and the streak is cleared only by a completed turn (`provider_turn_completed`, new delivery action), never at spawn, so repeated failed returns escalate 15m → 30m → 1h → … → 6h. The operator's `-m` retry still resets the streak. **Deploy:** host restart; no image rebuild. A container adopted across the restart runs its old runner and reports no answered turns, so a group's streak is cleared only once a container spawned after the restart answers. See [docs/provider-fallback.md](docs/provider-fallback.md#coming-back).
- **Chat SDK pinned to `4.41.1` (was `4.29.0`).** `chat`, `@chat-adapter/slack` and `@chat-adapter/discord` move together, and the `/add-<channel>` install pins and `setup/install-github.sh` move with them. The Slack adapter patch is gone: since 4.32 the shared `@chat-adapter/shared` scanner skips code spans and fenced blocks, emails, URLs and `<@U…>` tokens when rewriting `@mentions`, for Slack and Discord alike. One gap stays patched, now on that shared package: upstream reads a ``double-backtick`` span as two empty single-backtick spans and rewrites the `@name` inside it. `patches/@chat-adapter__shared@4.41.1.patch` cuts the same code regions the old Slack patch protected (fences of 3+ backticks, double-backtick spans across lines, one-line single-backtick spans) out of the text before the scanner runs, at the one entry point both adapters call (`src/channels/chat-adapter-code-spans.test.ts`). The fork's forwarded-message shim (`unwrapForwardedSnapshot` / `installForwardUnwrap`) is removed: since 4.38 the adapter folds `message_snapshots` text and attachments into the message itself, and running both delivered a forward's text and attachments twice. Forwards no longer carry the `[Forwarded message]` label; the snapshot text follows the author's text after a blank line. The Discord patch keeps only what upstream lacks: a one-week thread auto-archive and the sibling-bot allowance (`__nanoclawDiscordSiblings`) for messages and reactions; the `<@id>` double-wrap fix landed upstream in 4.33. Behaviour changes to know about: since 4.39 the Discord adapter resolves a thread's parent channel (`GET /channels/<thread>`, cached per thread afterwards) before first posting to it, so the message-thread auto-create shim now sees its 404 on that call and still creates the thread; since 4.40 the Slack adapter decodes the bot's own mention in inbound text and sets `isMention` from the raw event; since 4.41 adapters report an undetected mention as `undefined` rather than `false` (the SDK then falls back to text matching, and the router already tests `isMention === true`). **Deploy:** host restart; no image rebuild.

- [BREAKING] **Chat SDK pinned to `4.29.0` (was `4.26.0` via `^4.24.0`).** `chat` and the `@chat-adapter/*` channel adapters are version-locked — the adapter's `ChatInstance` must match the bridge's, so a mismatched pair fails to typecheck at `createChatSdkBridge(...)`. `chat` is therefore pinned exactly, and the channel-adapter install pins move with it — the dependency pins in the `/add-<channel>` SKILL.mds on `main`, plus the adapter code on the `channels` branch. Core installs with no channel (only `cli`) are unaffected. **Migration:** if any channel is installed (Slack, Discord, Telegram, Teams, …), re-run its `/add-<channel>` skill to pull the matching `4.29.0` adapter.
- **Budget/billing-exhausted LLM turns now reach the user instead of being silently dropped.** When a turn ends in a non-retryable provider error (e.g. an Anthropic `403 billing_error`) with no `<message>` wrapping, the agent-runner delivers the provider's notice to the originating channel and stops re-nudging the failing gateway. `providers/claude.ts` now surfaces the SDK's `is_error` flag (and the error subtype's `errors[]` text); `poll-loop.ts` delivers that text and skips the re-wrap retry. Fixes the case where a spend-limit notice produced silence plus a turn-after-turn retry loop.
- [BREAKING] **`@onecli-sh/sdk` 0.5.0 -> 2.2.1 — requires a OneCLI server with the `/v1` API** (older servers 404 every SDK call). The sanctioned gateway and CLI versions are pinned in `versions.json`. **The gateway is a separate component — updating NanoClaw does not upgrade it for you:** `/update-nanoclaw` upgrades it when the pin moves, otherwise upgrade manually. **Migration:** [docs/onecli-upgrades.md](docs/onecli-upgrades.md).
- **New agent provider: Codex (OpenAI) — run `/add-codex`.** Full runtime via `codex app-server` (planning, MCP tools, server-side history, resume). Trunk ships the seams and the skill; the payload installs from the `providers` branch (the skill, the setup picker, or `--step provider-auth codex`). Auth is vault-only — no credential ever enters a container.
- **Setup can now select, install, and authenticate a non-default agent provider.** A provider registry feeds the setup picker, an installer pulls the provider's payload from its branch, a vault auth walkthrough runs (`--step provider-auth`), and the picked provider is set on the first agent (a DB property) before its first spawn. Default (Claude) installs are unaffected — picking Claude changes nothing.
- **New groups inherit an instance-wide default provider.** `DEFAULT_AGENT_PROVIDER` in `.env` (default `claude`) sets which provider newly created agent groups get at creation; provider stays a per-group DB property, overridable via `ncl groups config update --provider` + restart. Existing groups are untouched — no migration, no retroactive flips.
- **Memory migrates via `/migrate-memory`, never through an implicit runtime import.** The workflow inventories every recognized group-local and provider-native source, retains a permanent checksummed snapshot, preserves collisions without overwriting, and activates one canonical workgroup tree only after verification. Provider-native paths become compatibility views of that canon; provider identity, instructions, credentials, and session state remain separate. See [docs/provider-migration.md](docs/provider-migration.md).
- **Per-exchange archiving is provider-owned** — the `onExchangeComplete` hook; the markdown writer ships with the codex payload.
- **Container boot failures now say why** — the last stderr lines are logged at `warn` on a non-zero exit instead of a silent crash loop.
- **Slash commands now interrupt an in-flight turn.** A runner-handled command (`/clear`, `/compact`, `/cost`, …) arriving mid-turn aborts the active stream and runs immediately instead of waiting out the turn.

## [2.0.0] - 2026-04-22

Major version. NanoClaw v2 is a substantial architectural rewrite. Existing forks should run `/migrate-nanoclaw` (clean-base replay of customizations) or `/update-nanoclaw` (selective cherry-pick) before resuming work.

- [BREAKING] **New entity model.** Users, roles (owner/admin), messaging groups, and agent groups are now tracked as separate entities, wired via `messaging_group_agents`. Privilege is user-level instead of channel-level, so the old "main channel = admin" concept is retired. See [docs/architecture.md](docs/architecture.md) and [docs/isolation-model.md](docs/isolation-model.md).
- [BREAKING] **Two-DB session split.** Each session now has `inbound.db` (host writes, container reads) and `outbound.db` (container writes, host reads) with exactly one writer each. Replaces the single shared session DB and eliminates cross-mount SQLite contention. See [docs/db-session.md](docs/db-session.md).
- [BREAKING] **Install flow replaced.** `bash nanoclaw.sh` is the new default: a scripted installer that hands off to Claude Code for error recovery and guided decisions. The `/setup` Claude-guided skill still works as an alternative.
- [BREAKING] **Channels moved to the `channels` branch.** Trunk no longer ships Discord, Slack, Telegram, WhatsApp, iMessage, Teams, Linear, GitHub, WeChat, Matrix, Google Chat, Webex, Resend, or WhatsApp Cloud. Install them per fork via `/add-<channel>` skills, which copy from the `channels` branch. `/update-nanoclaw` will re-install the channels your fork had.
- [BREAKING] **Alternative providers moved to the `providers` branch.** OpenCode, Codex, and Ollama install via `/add-opencode`, `/add-codex`, `/add-ollama-provider`. Claude remains the default provider baked into trunk.
- [BREAKING] **Three-level channel isolation.** Wire channels to their own agent (separate agent groups), share an agent with independent conversations (`session_mode: 'shared'`), or merge channels into one shared session (`session_mode: 'agent-shared'`). Chosen per channel via `/manage-channels`.
- [BREAKING] **Apple Container removed from default setup.** Still available as an opt-in via `/convert-to-apple-container`.
- **Shared-source agent-runner.** Per-group `agent-runner-src/` overlays are gone; all groups mount the same agent-runner read-only. Per-group customization flows through composed `CLAUDE.md` (shared base + per-group fragments).
- **Agent-runner runtime moved from Node to Bun.** Container image is self-contained; no host-side impact. Host remains on Node + pnpm.
- **OneCLI Agent Vault is the sole credential path.** Containers never receive raw API keys; credentials are injected at request time.
